# agent-ux — AI 페르소나 UX 검증 파이프라인

AI 페르소나가 웹사이트를 직접 조작하며 UX 문제를 찾는다.
대상은 `../ux-testbed/` 의 `clean` / `flawed` 두 벌 (결함 68건, 정답지 `DEFECTS.md`).

## 준비

```bash
# 1) 정적 서버 (터미널 하나를 계속 점유한다)
cd C:\Users\kamdo\AI_Testing
python -m http.server 8000

# 2) API 키 — 환경변수로만. 코드에 절대 넣지 않는다.
setx GEMINI_API_KEY "..."        # 한 번만. 새 터미널부터 적용된다
```

프로바이더는 `UXAGENT_PROVIDER` 로 갈아끼운다 (`gemini` 기본, `qwen` 가능).
모델 이름은 `uxagent/config.py` 의 `PROVIDERS` 한 곳에만 있다.

가용 모델 확인:

```bash
curl "https://generativelanguage.googleapis.com/v1beta/models?key=$GEMINI_API_KEY"
```

## 테스트

```bash
python smoke-test.py        # LLM 불필요. 서버만 떠 있으면 된다 (69개 항목, 약 20초)
```

'죽지 않는다'가 아니라 **측정 기준선이 흔들리지 않는다**를 검사한다.
clean 에서 시각 결함이 하나라도 세어지면 오탐률(차별점 ①)이 오염되므로 그게 곧 실패다.

| 묶음 | 내용 |
|---|---|
| 판단 표현 필터 | `"3개 이상"` 통과 / `"찾기 어렵다"` 검출 |
| URL 정규화 | `?id=7` 과 `?id=12` 가 같은 템플릿으로 접히는지 |
| 탐색 3층 | 양쪽 6/6, 디렉터리 층이 링크 사각지대를 메우는지 |
| 측정 기준선 | **clean 전 페이지 가려짐·저대비·키보드불가 = 0** |
| 결함 탐지 | buggy 의 D-05 / D-06 / D-10 이 잡히는지 |
| 답사 페르소나 | 설명서 형식이 정적 답사기와 같은지, 판단이 섞인 기록이 걸러지는지 |
| 탐색 루프 | 제자리·왕복 맴돌이를 잡는지, 허용 밖 행동이 막히는지, 이력이 3스텝인지 |
| 페르소나 조립 | 100명이 서로 다른 (조합, 목표) 쌍인지, 프롬프트 200자 이내인지, 10초 이상 머무는 인원이 0이 아닌지 |
| 시간 의존 | **D-26** 10초 후 자동 팝업 — 11초 기다렸다 가림 0→20 확인 |

마지막 항목이 없으면 `occluded` 는 양쪽 0이라 **탐지기가 도는지 증명되지 않는다.**
지표가 0이라는 것과 지표가 작동하지 않는다는 것은 다르다.

## 답사기 (survey.py)

사이트를 한 번 훑어 **지도**를 만든다. 저장 후 재사용하며, 100명 돌릴 때마다
다시 하지 않는다.

```bash
python survey.py --variant buggy            # 사람 확인 거쳐 maps/site_map_buggy.json
python survey.py --variant clean
python survey.py --variant buggy --mock --yes   # LLM 없이 파이프라인만 확인
python survey.py --variant buggy --validate-only # 저장된 지도 재검사
```

주요 옵션

| 옵션 | 뜻 |
|---|---|
| `--variant clean\|buggy` | `buggy` = 저장소의 `flawed/` 폴더 |
| `--extra 'product.html?id=999'` | 링크로 못 가는 특수 URL 수동 추가 (반복 가능) |
| `--no-local-dir` | 디렉터리 탐색 층을 끄고 남의 사이트와 동일 조건으로 테스트 |
| `--mock` | LLM 호출 없이 자리표시자로 전체 흐름 확인 |
| `--yes` | 사람 확인 단계 생략 |

### 지도에 무엇이 들어가고 무엇이 안 들어가나

```
지도  = 상태와 무관한 서술 (LLM)     -> layout, elements 이름
스냅샷 = 상태에 의존하는 수치 (코드)  -> 대비, 좌표, 접힘선, 가림
```

**측정값을 지도에 넣지 않는 이유**: 스크린샷을 본 LLM은 대비 비율을 계산할 수
없고 y좌표를 픽셀로 못 읽는다. 그럴듯한 숫자를 지어내는데, 틀린 숫자는 판단
표현 필터를 그냥 통과한다. 이 수치들은 `snapshot.py` 가 DOM/CSSOM에서
결정론적으로 계산하며 매 스텝 다시 뽑으므로 장바구니에 물건이 담겨 화면이
바뀌어도 낡지 않는다.

덕분에 지도에 없는 페이지에서 잃는 것은 서술 한 줄뿐이고, 시각 정보는 그대로
전부 들어온다.

참고용 수치는 `maps/survey_meta_*.json` 의 `reference_measurements` 에만 남는다.
**프롬프트에는 들어가지 않는다.** 사람이 눈으로 보고 clean/buggy를 대조하는 용도다.

### 답사자는 판단하지 않는다

답사자가 "슬라이더가 작동하지 않음"이라고 적으면 100명 전원이 그 문제를
'발견'한다. 적중률 100%가 나오지만 1명이 찾은 것을 100번 복사한 것이고
페르소나가 존재할 이유가 사라진다.

기준은 **카메라로 찍어서 확인 가능한가**다. "겹친다"는 사실이고 "가린다"는
판단이다. `uxagent/survey.py` 의 `BANNED_WORDS` 를 코드로 검사하며, 걸리면
최대 3회 재생성하고 그래도 남으면 저장하지 않고 중단한다.
LLM에게 자기 검증을 맡기지 않는다.

`"3개 이상"` 같은 수량 비교는 판단이 아니므로 검사 전에 걷어낸다
(`_NUMERIC_ISANG`).

### 답사가 못 가는 페이지

3층으로 찾는다.

| 층 | 방법 | 우리 테스트베드 |
|---|---|---|
| 1 | `<a href>` 링크 추적 | 5/6 |
| 2 | 로컬 디렉터리 목록 (정적 사이트 한정) | **6/6** |
| 3 | `--extra` 수동 추가 | 특수 상태 URL |

`complete.html` 은 `checkout.html` 의 `location.href` 로만 진입해 inbound
`<a>` 가 없다. 링크 추적으로는 원리적으로 도달 불가이며, 2층이 이를 메운다.
2층은 `--serve-root` 아래에 실제 폴더가 있을 때만 켜지고 남의 사이트에서는
자동으로 꺼진다.

남의 사이트라면 완전한 도달은 불가능하다. 그래서 **못 간 곳을 못 갔다고
말하는 것**이 이 도구의 신뢰 논리다. 페르소나 실행 중 `map_miss` 로 잡힌
URL을 `site_map.unreached` 에 채워 2회차에 보강하는 훅을 남겨두었다.

### URL 템플릿 정규화

`product.html?id=1..12` 를 그대로 세면 12페이지가 되어 답사 예산을 같은
템플릿 찍는 데 다 쓴다. `id/cat/q/page/sort` 는 페이지 '종류'가 아니라
'상태'로 보고 쿼리를 벗겨 6종으로 접는다 (`discover.template_key`).

## 페르소나 생성기 (generate.py)

지도를 보고 **목표 11개**를 만들고, **특성 조합 16개**와 엮어 100명을 조립한다.

```bash
python generate.py --mock --yes     # LLM 없이 (기본 목표 사용)
python generate.py                  # 지도를 보고 LLM이 목표 생성
python generate.py --validate-only  # 저장된 personas.json 재검사
```

저장 위치는 `personas/personas.json` (목표 + 100명) 과 `personas/personas_meta.json`.

### 왜 목표가 10개가 아니라 11개인가

조합이 16개다. 목표가 10개면 LCM이 80이라 81번째부터 앞 20명과 (조합, 목표)
쌍이 그대로 겹친다. 같은 조건을 두 번 돌려놓고 표본 100이라 부르게 된다.
11은 16과 서로소라 **100명 전원이 서로 다른 쌍**을 받는다 (스모크 테스트가 확인).

### 목표는 결함 목록이 아니다

"결제 버튼이 작동하는지 확인한다" 가 목표로 들어가면 100명 전원이 그 결함을
찾으러 간다. 적중률은 오르지만 우리가 미리 답을 알려준 것이다. 답사자에게
걸었던 금칙어 필터(`survey.BANNED_WORDS`)를 목표에도 그대로 건다.

경로 검사는 **템플릿 단위**로 한다. 지도는 `product.html?id=1..12` 를 한 줄로
접으므로 문자열로 비교하면 '품절 상품(`?id=7`)을 사러 간다' 같은 정당한 목표가
거부된다. 마찰을 일부러 만드는 목표를 검사기가 지우면 안 된다.

### 상태는 코드가 만든다 (답사와 같은 원칙)

목표 문장은 LLM이 쓰지만 `seed_state`(장바구니에 뭐가 담겨 있는가)는 코드가
만든다. LLM이 지어낸 장바구니는 상품 id나 가격이 틀려도 문장 검사를 그냥
통과하고, 틀린 채로 100명에게 배포된다.

⚠ **`seed_state` 에 localStorage 키를 넣지 않는다.** 키가 변형마다 다른데
(`moji_cart_clean` / `moji_cart_flawed`) 페르소나 파일은 양쪽에 동일하게
투입되므로(결정 6), 키를 박으면 한쪽이 조용히 빈 장바구니가 되고 유형 C
목표가 통째로 무력화된다. 키는 러너가 `config.cart_key(variant)` 로 붙이고,
시딩 JS는 `persona.seed_script()` 가 만든다. 가격·이름은 두 변형이 공유하는
`window.PRODUCTS` 에서 읽으므로 파이썬에 가격표를 복사하지 않는다.

사이트의 `addToCart()` 를 부르지 않는 이유: flawed 쪽 `addToCart` 자체가
결함일 수 있다. 준비 단계가 검사 대상 코드에 의존하면 '재방문자'가 한쪽에서만
빈 장바구니로 시작하고, 그 차이가 결함 탐지 결과로 둔갑한다.

### 체류 시간과 D-26

D-26(자동 팝업)은 로드 **10초 후**에 뜬다. 전원이 5초 만에 떠나면 Critical
결함 하나를 아무도 만나지 못하고, 그건 '못 잡은 것'이 아니라 '마주친 적이
없는 것'이다. `persona.DWELL_MS` 가 정독x여유 조합에 12초를 주어 **26명**이
10초 문턱을 넘는다. 스모크 테스트가 이 인원이 0이 아닌지 검사한다.

### 분석할 때 주의 — traits.visit 이 아니라 user_type 으로 묶을 것

유형 C 목표는 시딩을 요구하므로, `traits.visit == "new"` 인 페르소나도
장바구니가 채워진 채 시작할 수 있다 (프롬프트 문장도 재방문 쪽으로 바뀐다).
100명 중 시딩 67명 / 빈 장바구니 33명. **신규 vs 재방문 비교는 `user_type`
필드로 묶어야 한다.** `traits.visit` 으로 묶으면 재방문 행동을 신규 쪽에
섞어 세게 된다.

## 실행기 (run.py)

페르소나를 실제로 사이트에 풀어놓고 스텝마다 전부 기록한다.

```bash
python run.py --variant buggy               # 기본: 한 명만
python run.py --variant buggy --headed      # 창을 띄우고 한 명 (시연용)
python run.py --variant buggy --limit 3
python run.py --variant buggy --all         # 100명 (한 번 더 묻는다)
python run.py --variant buggy --mock        # LLM 없이 루프만
python run.py --variant buggy --no-map      # 지도 없이 (A/B 대조군)
```

**기본이 한 명인 이유**: 스텝마다 LLM을 부른다. 100명 × 최대 30스텝이면 한 번에
3,000회다. 실수로 전부 도는 일이 없도록 100명은 `--all` 을 명시해야 하고,
그때도 예상 호출 수를 먼저 보여준 뒤 한 번 더 묻는다.

| 옵션 | 뜻 |
|---|---|
| `--max-usd 1.0` | 이 금액을 넘으면 그 자리에서 멈춘다 (기본 $1) |
| `--max-calls N` | 호출 수 상한 |
| `--parallel N` | 동시 실행. 기본 1 (창을 띄울 땐 1이 낫다) |
| `--only P009` | 특정 페르소나만. 반복 지정 가능 |
| `--quiet` | 스텝별 출력 끄기 |

상한에 걸려 멈춘 사람의 종료 사유는 **`budget_stop`** 이다. 우리가 끊은 것을
`gave_up` 으로 적으면 "포기가 몰린 지점이 진짜 마찰 지점"이라는 판단 근거가
그대로 오염된다.

### 한 스텝에서 일어나는 일

```
새 화면이면 dwell_ms 만큼 머문다   (D-26 자동 팝업은 로드 10초 후)
  → snapshot.py 로 화면을 잰다
  → 페르소나 프롬프트 + 지도 슬라이스 + 계산된 시각 정보 + 최근 3스텝
  → LLM: {"thought": "...", "action": {"type": "click", "target": "link_3"}}
  → allowed_actions 검사 → 목록 밖이면 실행하지 않고 blocked_action 으로 기록
  → 이름(data-agent-id)으로 실행. 좌표로 누르지 않는다
  → trace.py 형식으로 기록. 한 명이 끝나면 그 자리에서 파일 저장
```

클릭 실패는 오류가 아니라 **마찰의 기록**이다. "눌렀는데 아무 일도 일어나지
않았다"가 그대로 남아야 한다.

### 언제 멈추는가

`goal_reached` / `gave_up` / `max_steps` / `loop_detected` / `budget_stop` / `error`.

맴돌이는 두 가지를 본다. **제자리**(같은 화면에서 같은 행동 반복)와
**왕복**(A→B→A→B). 왕복을 안 잡으면 30스텝을 다 태우고 `max_steps` 로 찍혀서
'스텝이 모자랐다'와 '길을 잃었다'가 구분되지 않는다. 실측으로 모의 실행이
30스텝 → 6스텝으로 줄었다. 스텝이 곧 토큰이다.

### 나오는 것

```
logs/{run_id}/index.json      누가 어디서 왜 끝났나
logs/{run_id}/P001.json       스텝마다 생각 / 행동 / 그 순간 화면 전체
```

스텝마다 스냅샷을 통째로 남긴다. 나중에 다시 계산할 수 없기 때문이다 —
장바구니에 3개 담긴 상태의 접힘선은 그 순간에만 존재한다.
**실측 30스텝 = 310KB**, 100명이면 약 31MB.

## 답사 페르소나 (scout.py) — 스크린샷을 찍으며 직접 조작

`survey.py` 는 페이지마다 들러 사진을 찍는 **정적 촬영**이다. 링크로 갈 수 있는
곳만 찍히고, **눌러야 나오는 화면은 원리적으로 못 본다.**

`scout.py` 는 답사자를 **한 명의 탐험가**로 만든다. 스텝마다 스크린샷을 찍고,
본 것을 기록하고, 다음에 무엇을 눌러볼지 스스로 정한다. 상품을 담고 결제를
완주하면 결제 완료 화면이 설명서에 들어간다.

```bash
python scout.py --variant clean --mock --yes     # LLM 없이 루프 확인
python scout.py --variant clean --headed         # 돌아다니는 것을 보며
python scout.py --variant buggy --max-steps 60 --shots-dir shots/
```

결과 파일은 `survey.py` 와 **같은 형식**(`maps/site_map_*.json`)이라 generate.py 와
run.py 는 아무것도 고칠 필요가 없다. 기존 지도는 `.bak` 으로 백업한다.

### 도달 범위 (모의 실행 실측)

| | 정적 촬영 (survey.py) | 답사 페르소나 (scout.py) |
|---|---|---|
| 링크만 (`--no-local-dir`) | 5/6 | **6/6** |
| 로컬 디렉터리 층 포함 | 6/6 | 6/6 |
| `complete.html` 도달 방법 | 폴더 목록에서 파일명을 주움 | **결제를 완주해서** |

`complete.html` 은 `checkout.html` 의 `location.href` 로만 진입해 inbound `<a>` 가
없다. 정적 촬영은 로컬 정적 사이트일 때만 켜지는 디렉터리 층으로 겨우 메웠고,
**남의 사이트에서는 그 층이 꺼진다.** 답사 페르소나는 조작만으로 닿으므로
그 제약이 사라진다.

flawed 쪽은 5/6이다. 결제가 완주되지 않아 완료 화면에 못 갔고, 그것은
`unreached` 에 사실로 남는다. 판단하지 않는다 — 못 간 곳을 못 갔다고 적을 뿐이다.

### 성격은 주되 판단은 금지

탐험가에게 성격을 준다("구석구석 눌러보고 끝까지 가봐야 직성이 풀린다").
성격은 **어디를 눌러볼지**를 정할 뿐이고, 기록은 여전히 사실만 남는다.
답사자가 "여기 불편함"이라고 적으면 100명 전원이 그 문제를 '발견'하고,
적중률 100%는 1명이 찾은 것을 100번 복사한 값이 된다.
판단 표현이 섞인 기록은 **그 화면 기록만 버리고** 답사는 계속한다.

### 이미지 호출 수

페르소나 한 명분이다. 40~60스텝이면 40~60회. 뒤따르는 100명은 이 설명서만
읽고 **이미지를 한 장도 쓰지 않는다.** 스텝마다 이미지를 주는 방식이었다면
100명 × 30스텝 = 3,000회다.

⚠ `--dry-rounds` 기본값은 15다. 결제 폼 하나를 채우는 데만 6~10스텝이 들어서,
낮게 잡으면 폼 앞에서 답사가 끝난다 (실측: 8이면 결제 화면에서 중단).

## 기록 읽기 (diary.py)

뷰어가 나오기 전까지 쓰는 도구다. 로그를 사람이 읽는 글로 바꿔 터미널에 뿌린다.

```bash
python diary.py                     # 가장 최근 기록
python diary.py --list              # 있는 기록 전부
python diary.py logs/scout_clean_0825_1419.json
python diary.py logs/0825_1332_clean/P001.json --full   # 좌표·실패 사유까지
```

두 종류를 다 읽는다.

| 파일 | 무엇 |
|---|---|
| `logs/scout_*.json` | 답사자가 **설명서를 어떻게 만들었나** — 어디서 뭘 눌렀고 어느 화면을 적었나 |
| `logs/{run_id}/P0xx.json` | 페르소나가 **목표를 어떻게 좇았나** — 스텝별 생각·행동·그 순간 화면 |

페르소나 쪽은 화면이 바뀔 때마다 계산된 수치를 한 줄로 얹는다.

```
── index.html  (쇼핑몰)
   화면: 요소 30 · 접힘선아래 7 · 가려짐 20 · 저대비 30 · 키보드불가 10
   1. 가리고 있는 것을 먼저 닫겠습니다.
      누름 span_1   → 화면이 바뀌지 않았습니다
```

`★ 설명서에 적음`(답사자), `⨯ 허용되지 않은 행동`, `[설명서에 없는 화면]`(map_miss)
표시가 붙는다.

## 뷰포트

`config.VIEWPORT = 1280x800`. 값의 유일한 출처이며 다른 모듈은 이걸 읽는다.

- 레이아웃이 `.wrap{width:1180px}` 고정이라 1280이든 1440이든 렌더 결과가 같다
- 높이 800이 900보다 접힘선이 위여서 `below_fold` 마찰이 더 드러난다

⚠ 데스크톱 전용이므로 375px에서만 드러나는 **D-28 / D-29 / D-30 3건은
페르소나가 원리적으로 못 잡는다.** 채점 시 상한으로 명시할 것.
