페이지마다 한 장씩 찍는 정적 촬영이라 '눌러야 나오는 화면'을 못 봤다.

- 결과 파일 형식은 survey.py 와 **동일**(`maps/site_map_*.json`). generate/run 무수정.
  기존 지도는 `.bak` 으로 백업하고 덮는다.
- **모의 실측: `--no-local-dir`(남의 사이트 조건)에서 clean 6/6.**
  complete.html 에 결제를 완주해서 도달했다 (26스텝). 정적 촬영은 같은 조건에서 5/6.
- flawed 는 5/6. 결제가 완주되지 않아 완료 화면 미도달 → `unreached` 에 사실로 기록.
- 성격은 주되 판단은 금지. 판단 표현이 섞인 기록은 **그 화면만 버리고** 계속한다.
- `--dry-rounds` 기본 15. 결제 폼 하나가 6~10스텝을 먹어서 8이면 폼 앞에서 끝난다.
- 이미지 호출은 스텝 수만큼(40~60회). 발표의 "이미지 3,000회 → 40회" 가 이제
  실제 설계와 맞는다. 100명은 이미지 0회.

⚠ 지금 maps/ 의 지도는 **모의(mock) 자리표시자**다. 크레딧이 붙으면
`python scout.py --variant clean` 과 `--variant buggy` 를 실제로 한 번씩 돌릴 것.

## 남은 작업에서 놓치면 안 될 것

- A/B 검증에 **clean 대조군을 반드시 포함** (4회 실행). 지도가 재현율만 올렸는지,
  오탐도 같이 올렸는지 봐야 한다. 재현율만 오르면 채택, 둘 다 오르면 기각
- 발표 수치 주의: "이미지 3,000회 → 40회" 는 우리가 겪은 적 없는 과거와의 비교다.
  우리 설계는 원래 0회였고 40회는 **증가**다. UXAgent 방식 대비 절감이라고 명시할 것.
  "60분 → 30분" 도 러너가 없어 근거 없음. 실측 후에 쓸 것
- 페르소나마다 `browser.new_context()`, 끝나면 `context.close()`
- 프롬프트에 **최근 3스텝만**
- **한 명 끝날 때마다 즉시 파일 저장**
- 종료 사유 4종: `goal_reached` / `gave_up` / `max_steps` / `loop_detected`
  → "포기"와 "스텝 소진"은 다른 신호. 포기가 몰리는 지점이 진짜 마찰 지점
- 온도: 탐색 1.0 / 목표생성 0.7 / 답사·분석 0.0
- 탐색 중엔 이슈 분석 절대 안 함 (분석은 완전 별개 단계)
- 페르소나 프롬프트 **200자 이내**, 배경 서사 금지, 특성→문장 매핑 딕셔너리로 조립
- `allowed_actions` 는 러너가 실제로 강제. 목록 밖 행동은 `blocked_action` 으로 로그
- 프롬프트에 "반드시 한국어로 답하라" 명시
- 뷰어는 단일 HTML, 빌드 없음, 다크 모드, CDN 최소화
