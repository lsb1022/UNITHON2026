# 페르소나 실행 안내서

이 문서만 보고 따라 하면 됩니다. 코드를 고칠 필요는 없습니다.
**하는 일은 하나뿐입니다: 이미 만들어진 AI 페르소나를 쇼핑몰에 풀어놓고 기록을 남기는 것.**

---

## 0. 이게 무슨 프로젝트인가 (30초)

AI 페르소나 여러 명이 쇼핑몰을 직접 조작하며 목표를 수행합니다.
목표는 전원 같습니다 — **"코튼 셔츠를 장바구니에 담아 주문까지 마친다"**.
사람마다 성격이 달라서(숙련도·주의력·인내심·탐색범위 각 1~5단계) 어떤 사람은 해내고
어떤 사람은 중간에 포기합니다. **그 차이가 결과물입니다.**

쇼핑몰은 두 벌입니다.

| 이름 | 뜻 |
|---|---|
| `clean` | 정상판. 잘 만든 쇼핑몰 |
| `buggy` | 결함판. UX 문제를 일부러 68개 심어놓은 같은 쇼핑몰 |

---

## 1. 준비 (한 번만)

### 1-1. 정적 서버가 떠 있어야 합니다

쇼핑몰이 `http://localhost:8000` 에서 돌아가야 페르소나가 접속할 수 있습니다.
**새 PowerShell 창**을 열고:

```powershell
cd C:\Users\kamdo\AI_Testing
python -m http.server 8000
```

이 창은 **끄지 말고 그대로 두세요.** 아래 내용이 나오면 정상입니다:

```
Serving HTTP on :: port 8000 (http://[::]:8000/) ...
```

확인: 브라우저에서 http://localhost:8000/ux-testbed/clean/index.html 을 열어
쇼핑몰이 보이면 됩니다.

### 1-2. API 키를 넣습니다

**또 다른 PowerShell 창**을 열고 (여기서 실제 작업을 합니다):

```powershell
$env:GEMINI_API_KEY = "여기에_키를_붙여넣으세요"
$env:UXAGENT_PROVIDER = "gemini"
```

> ⚠ 이 창을 닫으면 키가 사라집니다. 창을 새로 열 때마다 다시 넣어야 합니다.

### 1-3. 연결 확인 (돈 거의 안 듦)

```powershell
cd C:\Users\kamdo\AI_Testing\agent-ux
python check-llm.py
```

**"전부 통과"** 가 나오면 준비 끝입니다.

안 되면 메시지를 그대로 보고하세요:
- `429` → 크레딧이 없습니다. 키 발급자에게 문의
- `401` / `403` → 키가 틀렸습니다
- `404` → 모델 이름 문제 (보고만 하세요)

## 2. 실행하기

### 기본 형태

```powershell
cd C:\Users\kamdo\AI_Testing\agent-ux
python run.py --variant clean --limit 5 --parallel 2 --max-usd 0.5 --run-id 실행이름
```

### 옵션 뜻

| 옵션 | 뜻 | 권장 |
|---|---|---|
| `--variant` | `clean`(정상판) 또는 `buggy`(결함판) | 둘 다 해봐야 비교가 됩니다 |
| `--limit N` | 앞에서 N명 | 5~10 |
| `--only P011` | 특정 사람만 (여러 번 쓸 수 있음) | |
| `--parallel N` | 동시에 N명 실행 | **2~3** (더 올리면 노트북이 버벅입니다) |
| `--max-usd 0.5` | 이 금액 넘으면 자동 중단 | **꼭 넣으세요** |
| `--run-id 이름` | 결과 폴더 이름 | **매번 다르게** |
| `--quiet` | 진행 로그를 줄입니다 | 여러 개 돌릴 때 |
| `--headed` | 브라우저 창을 띄워 눈으로 봅니다 | `--parallel 1` 과 함께 |

### 이렇게 해주세요 (순서대로)

```powershell
# ① 정상판 10명
python run.py --variant clean --limit 10 --parallel 2 --max-usd 0.5 --run-id run_clean_01

# ② 결함판 10명 (같은 사람들)
python run.py --variant buggy --limit 10 --parallel 2 --max-usd 0.5 --run-id run_buggy_01

# ③ 다른 사람들로 한 번 더
python run.py --variant clean --only P011 --only P012 --only P013 --only P014 --only P015 --parallel 2 --max-usd 0.4 --run-id run_clean_02
python run.py --variant buggy --only P011 --only P012 --only P013 --only P014 --only P015 --parallel 2 --max-usd 0.4 --run-id run_buggy_02
```

**한 번에 하나씩** 돌리세요. 앞 명령이 끝나야 다음 것을 시작합니다.

### 얼마나 걸리나

한 명당 1~2분입니다. `--parallel 2` 로 10명이면 **8~12분**.
화면에 이런 게 흐르면 정상입니다:

```
  [P003]  4/20  click link_8
        상품 목록에서 코튼 셔츠를 눌러 상세 페이지로 갑니다.
  [P003] goal_reached — 12스텝
```

## 3. 끝나면 확인하기

실행이 끝나면 마지막에 요약이 나옵니다:

```
  goal_reached   7명       ← 목표 달성
  gave_up        1명       ← 포기
  loop_detected  2명       ← 같은 자리에서 맴돌다 중단
  호출 124회 / 약 $0.164
```

더 자세히 보려면:

```powershell
python diary.py --list                                  # 기록 목록
python diary.py logs\run_clean_01\P003.json             # 한 사람 읽기
python report.py run_clean_01 run_buggy_01 --out 비교.md  # 두 실행 비교 문서
```

## 4. 하지 말아야 할 것

| 하지 말 것 | 이유 |
|---|---|
| `python generate.py` 실행 | 페르소나 100명을 다시 만듭니다. 그러면 **앞서 돌린 결과와 사람이 달라져** 비교가 깨집니다 |
| `personas/personas.json` 열어서 수정 | 위와 같은 이유 |
| `--run-id` 를 같은 이름으로 두 번 | 로그가 섞입니다 |
| `--parallel 5` 이상 | 크롬이 5개 뜨고 API 요청이 몰려 실패합니다 |
| `--max-usd` 없이 `--all` | 100명이 돌아 예상보다 많이 씁니다 |
| `server/`, `web/` 폴더 건드리기 | 다른 사람이 작업 중입니다 |

## 5. 문제가 생기면

| 증상 | 원인과 대처 |
|---|---|
| `페르소나 파일이 없습니다` | `agent-ux` 폴더에서 실행했는지 확인 |
| `지도가 없습니다` | 같음. 경로 확인 |
| 모든 클릭이 `시간 초과` | 정적 서버(1-1)가 꺼졌는지 확인 |
| `429` | 크레딧 소진. **즉시 멈추고 보고** |
| `503` | 모델 혼잡. 자동으로 다른 모델로 넘어갑니다. 계속 나오면 10분 뒤 재시도 |
| 진행이 3분 넘게 멈춤 | `Ctrl+C` 로 중단하고 보고 |

**어떤 오류든 화면에 나온 메시지를 그대로 복사해서 보고해주세요.** 요약하지 마세요.

## 6. 끝나고 보고할 것

각 실행마다:

1. `--run-id` 이름
2. `clean` 인지 `buggy` 인지
3. 마지막 요약 줄 (달성/포기/맴돌이 인원수, 호출 수, 금액)
4. 이상한 점이 있었다면 그 화면 그대로

예시:

```
run_clean_01 (clean, 10명)
  goal_reached 7 / gave_up 1 / loop_detected 2
  호출 124회 / $0.164
  특이사항: P005 가 20스텝 넘게 결제 화면에서 맴돌았음
```
